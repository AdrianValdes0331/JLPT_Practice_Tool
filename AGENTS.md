# Agent guide: JLPT Practice Tool

Read [README.md](README.md) first: it documents running the app and the CSV data format (the source of truth for content).

## Architecture
- Electron app, no frontend framework, no bundler. Plain JS/CSS in `renderer/`.
- `main.js`: window only (`contextIsolation` on, `nodeIntegration` off, sandboxed). No preload/IPC; keep it that way unless a feature needs it.
- `data/*.csv` is the only content source. `tools/build_data.js` validates and merges it into the generated `renderer/data.js` (`window.DATA`). Never edit `renderer/data.js` by hand; it is regenerated on `npm start`.
- Example sentences are optional and live in `data/sentences/*.csv` (`section,word,ja1,en1,ja2,en2,ja3,en3`, max 3). The build attaches them as `entry.sentences: [{ ja, en, furi? }]` by `section|word`; missing ones must never fail the build or the UI. `furi` is a ruby segment list (string = plain text, `[base, reading]` = ruby) generated by kuroshiro at build time; `漢字[よみ]` in a CSV cell forces a reading, and `FURIGANA_FIXES` in `tools/build_data.js` corrects the analyzer globally. Missing kuroshiro must also never fail the build.
- `renderer/app.js`: all UI and quiz logic in one IIFE. DOM is built with the `h()` helper (no `innerHTML`), which keeps data like `&` safe under the CSP in `index.html`.
- `renderer/styles.css`: dark glassmorphism theme driven by CSS variables in `:root`. Reuse existing classes (`glass`, `chip`, `btn`, `grid`, `cat`, `opt`) before adding new ones.
- Progress is stored in `localStorage` under `jlpt-progress-v2` (`{ size, section, level, words: { [entry.key]: { seen, missed } } }`).

## Data model
Entry: `{ key: "section|word|reading", section, word, reading, meaning, tags: [{ level, category }], sentences?: [{ ja, en, furi? }] }`. One entry can have many tags (cross product of `|`-separated levels and categories). A pool is the set of entries matching `{ section | "random", level | "all", category | "all" | "review" | name }`.

## Quiz rules (keep consistent when changing behaviour)
- Per item: step 1 reading (6 options), step 2 meaning (6 options). Score counts first attempts only.
- Kana-only items (word equals reading, katakana compared as hiragana) skip step 1 and go straight to the meaning.
- Distractors come from the same section as the item, favouring similar readings/shared categories; they never duplicate the correct answer or another option (meanings compare by first `;` segment).
- No repeats until the pool is exhausted (`seen` flag), then a new round starts.
- Missed items: re-queued once at the end of the set, flagged `missed`, and up to half of later sets are drawn from missed items. A clean pass clears the flag.
- Keyboard: 1–6 answer, Enter/Space next, S show/hide example sentences, Esc back home.

## Conventions
- Adding a section: add its id to `SECTIONS` in `renderer/app.js` and to `SECTIONS` in `tools/build_data.js`, and document it in README.md.
- `mdiccionary` (M.Diccionary) is standalone: listed in `STANDALONE` in `renderer/app.js`, so Random excludes it. Its meanings are Spanish and are kept verbatim. Unfinished work is tracked in `Pending.md`.
- Adding levels or columns: update `tools/build_data.js` validation, `README.md` and this file together.
- Changing the stored progress shape: bump `STORE_KEY` and migrate or accept a reset.
- Keep comments short and only for non-obvious intent. Don't add markdown docs beyond README.md and this file unless asked.

## Environment gotchas
- Windows / PowerShell; chain commands with `;`.
- Corporate proxy breaks Electron's download: see the `NODE_OPTIONS=--use-system-ca` note in README.md.
- `Description_old.txt` is the spec of the original React prototype, kept for reference only.

## Verify changes
`npm run build-data` (validates CSVs), `node --check renderer/app.js`, then `npm start` and exercise one set per section.
